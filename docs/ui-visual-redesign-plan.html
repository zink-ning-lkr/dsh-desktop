00结论摘要

现有界面的工程质量极高(令牌化、深浅双主题、A11y、UITEST 像素契约、懒创建内存治理),但视觉气质是「GitHub 皮肤」而非「DSH 品牌」:色板逐字复刻 GitHub Dark/Light、命令栏 30px 内塞进 10 个控件、辅助窗五窗五种布局范式、全部按钮只有一种 30px 规格、动效零性格。

主张一:色板从「GitHub 灰黑」转向「深海冷调」

基底由 #0d1117(纯灰黑)改为冷调深海军蓝 #0b0f1d,文字带冷白,边框带蓝灰——所有令牌名不变,只换值。品牌蓝紫 #4d6bfe → #7aa1ff 渐变成为唯一强调色,语义色换用现代高饱和四色(青/琥珀/玫红)。改动面收敛在 ui.css 一处。

主张二:每个界面有自己的「角色」,不再五窗一貌

命令栏=信息中枢、任务中心=卡片流、对话框=聚焦弹层、设置窗=分区表单、报告窗=诊断仪表、欢迎/加载=品牌舞台。逐页给出布局、材质、动效、逐按钮规格(§4 十二节)。

主张三:按钮从「一种 30px」升级为「五档规格体系」

主操作(渐变)/ 次级(描边)/ 幽灵(文字)/ 危险(红系)/ 图标(三档尺寸),每档定义 4 态(hover/active/disabled/focus)+ 品牌化按压与光晕(§5)。

1.2 十个视觉问题(按优先级)

V1色板是 GitHub 皮肤,不是 DSH 品牌P0

深色 6 个底色(#0d1117/#161b22/#21262d/#30363d/#e6edf3/#8b949e)与浅色 6 个底色逐字复刻 GitHub;唯一品牌痕迹是 #4d6bfe 按钮与 #8b5cf6 进度副色。用户看到的是「又一个 GitHub 风工具」,与 DeepSeek 品牌(深蓝+鲸鱼)零关联。

V230px 命令栏信息过载P0

一条栏里:☰、鲸鱼、DSH、工作目录(最长 46vw)、命令入口胶囊、服务点、任务徽标、更新徽标、主题钮、收起、最小化、最大化、关闭——13 个元素。工作目录与命令入口在 960-1200px 区间互相挤压,<960px 命令入口整体消失(只能靠 Ctrl+K)。状态点 8px 圆点,语义全靠颜色,色弱用户无法区分。

V3辅助窗「五窗一貌」,布局范式各自为政P0

dialog 居中弹层、status 顶部进度、settings 分区表单、report 顶部诊断、welcome 居中 hero——头部都是同一个 .win-head,但内容区五种范式。用户在不同窗之间切换时没有一致的「信息阅读顺序」。

V4按钮只有一种 30px 规格P1

.btn 单一规格 + 5 个变体(primary/success/danger/danger-ghost/默认)。行内只有 status 有小按钮(26px)。没有文字按钮/图标按钮档位,「清除镜像」用 danger-ghost 却无图标,「刷新内存」是裸文本按钮。视觉权重无法表达操作层级。

V5动效零性格,全是保守 fade/slideP1

入场动画 = opacity + 位移(菜单/面板/toast/窗口),全部 0.16-0.24s;唯一有性格的是加载页鲸鱼呼吸与进度条 sheen。没有任何品牌化动效(光波、涟漪、渐变流动),reduced-motion 之外的观感「没有记忆点」。

V6Win11 材质只试点不铺开,且配合保守P1

acrylic/mica 只覆盖 status/dialog/settings/report 四窗;菜单/面板/toast/托盘仍是纯色卡片。材质窗的 --win-bg 只做到 55-62% 透明度,圆角 10px,自绘阴影直接去掉——玻璃感不完整。

V7图标描边规范不统一P1

menu/cmdbar/toast 族 stroke-width 1.3,result/activity 族 1.6-1.7,linecap 有的 round 有的 butt;同是 16 viewBox 的图标在 15px 与 13px 间混用(palette.search 13px)。放大后粗细不齐、端点形态不一。

V8信息密度与层级:日志/表单偏挤,主窗偏空P1

report 日志 12px 等宽、设置窗 12px 表单、toast 12px 单行——密集区域字号压到极限;而主窗 1440px 宽只有 30px 命令栏 + dsh 页面,壳层几乎隐形。

V9状态反馈分散在三种载体,风格不一P2

就地反馈(inline-feedback 文本)、toast(卡片)、系统通知——同是「已保存」类反馈,三种长相。对话框 detail 面板、设置窗 .cmd 卡片、报告 cause 块,三处都是「下沉面板」但圆角/底色各写各的。

V10欢迎/加载两扇品牌门面最朴素P2

首启欢迎页与启动加载页是用户对 DSH 的第一印象,却只是「居中 logo + 一段文字」;没有品牌渐变、没有玻璃、没有鲸鱼叙事。

02设计方向:深澜(DEEP TIDE)

2.1 四个候选方向

方向气质代表参照优点风险结论
A · 深澜 深海冷调
(推荐)		 深海蓝黑基底 + 品牌蓝紫光 + 波光动效 DeepSeek 品牌 / Linear 冷调深色 与品牌强关联;色板改动收敛在令牌层;浅色=海面晨光,双主题叙事完整 偏离 GitHub 系后对比度需重验;视觉「冷」,部分用户可能不喜 推荐
B · 全玻璃拟态 Mica/Acrylic 全铺,半透明分层,大圆角 Windows 11 Fluent / macOS Sonoma 系统原生感强,Win11 上惊艳 Win10 降级差异大;模糊在低端机有 CPU 成本;截图/UITEST 不稳 作为 A 的渐进增强,不单独成体系
C · 极简单色 中性灰白、大留白、字体层级驱动 Vercel / Arc / Linear 浅色 高级、克制、对比度好把控 与「开发者工具」气质重叠;品牌感弱;深色用户无感 作为浅色主题的底子
D · 终端/命令行美学 mono 字体主导、终端绿、极密 Warp / Neovim 生态 与 dsh 开发者身份契合 对非开发者用户不友好;长期使用视觉疲劳 作为「开发者模式」可选皮肤,本轮不做

2.2 深澜体系的五个设计原则

  1. 品牌即底色:色板从 GitHub 灰黑转向深海冷调蓝黑;唯一强调色 = DeepSeek 蓝紫渐变。任何界面一眼认出「这是 DSH,不是别的壳」。
  2. 光从海底来:深色界面用「上冷下深」的微渐变表达光线;强调元素带品牌光晕(glow);进度/加载用波光(现有 sheen 升级为品牌蓝紫流光)。
  3. 每窗有角色:十二界面各定一种布局范式(§4),窗口之间信息阅读顺序一致(头→内容→脚)。
  4. 层级靠「层」不靠「线」:用圆角+半透明分层+冷调阴影表达浮起,减少对 1px 边框的依赖;Win11 材质作渐进增强。
  5. 动效有记忆点:三档时长保留,但每个关键动效给一个品牌签名(菜单滑入带光晕、面板回弹、toast 波光尾迹、状态点呼吸)。全程尊重 prefers-reduced-motion。

一句话主张

「把 DSH 从 GitHub 皮肤 变成 深海里的光」——色板冷调化、玻璃铺开、按钮五档化、每窗有角色, 用品牌蓝紫作为整座应用唯一的光源,让十二个界面共用同一套「深海」叙事。

7.1 不可动硬约束(违反会出事)

  • 禁止 ES module:页面走 file://,全部共享层保持经典 script + IIFE + window.*。
  • CSP 不放松:无外部 CDN/字体(新增字栈只能用系统内置 Bahnschrift/Segoe UI)。
  • build.files 白名单:新增文件(如有)必须逐条加入 package.json。
  • UITEST 几何契约:命令栏高 30、status 186/250、menu item 32/sec 24/sep 9、dialog min 200、面板 560/行 36——除非同提交改断言,否则不许动。
  • IPC 信道与载荷:acc:get/set/close、st:、dl:、rp:、tb:、m:、pt:、nt:、wl:、boot: 全部保持;新增 IPC 只能新增不能改签名。

  • 安全面:trustedEvent 首行校验、dsh-preload 对远程页零暴露、文本一律 textContent——视觉改动不得引入 innerHTML 注入面。
  • 点击穿透与焦点:toast 的 setIgnoreMouseEvents、菜单/面板 blur 收起、焦点陷阱、aria-activedescendant 全部保持。
